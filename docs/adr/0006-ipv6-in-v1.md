# IPv6 is in scope for v1, on both axes

Frank dials over IPv6 and evaluates `ip6:` mechanisms from day one. On the transport
side this is free: `net.Dialer` already resolves A and AAAA and runs Happy Eyeballs, so
suppressing v6 with `"tcp4"` is the extra line, not enabling it. On the evaluation side
it is not optional. An SPF mechanism Frank refuses to parse is an unknown mechanism, and
RFC 7208 makes that a `permerror`, so declaring v6 out of scope means deliberately
emitting wrong Verdicts for every record containing `ip6:`. That is the failure
ADR-0002 exists to prevent.

`net/netip` collapses both families into one code path. `netip.ParsePrefix` accepts
`192.0.2.0/24` and `2001:db8::/32` identically, and `Prefix.Contains(Addr)` is the whole
`ip4`/`ip6` matcher.

## Consequences

Every address entering SPF evaluation must be normalized with `.Unmap()` first, and
addresses carrying a zone must be rejected. `conn.LocalAddr()` can return
`::ffff:192.0.2.1` for a connection made over IPv4, and `Prefix.Contains` returns false
when bit lengths differ, so an unnormalized Source Address produces a confident `fail`
where the truth is `pass`. Verified against Go 1.26.2: the mapped address fails to match
`192.0.2.0/24` and matches after `.Unmap()`. That normalization call looks like noise.
Deleting it silently corrupts Verdicts.

Zone fixtures and matcher tests carry a v6 twin for each v4 case.
